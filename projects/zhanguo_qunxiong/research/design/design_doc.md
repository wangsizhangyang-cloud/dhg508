## 背景与语境

Week 8 的题目是 **A Historical Simulation**：重建一个真实的历史情境，让人可以进入、观察、尝试；每一部分都要来自史料，或明确标注不是。课程特别追问：**为什么是模拟，而不是一部电影？**

本项目选的是 **西周灭亡 / 骊山之难（前 771 年）**，视角放在秦襄公：幽王废申后与太子宜臼，立褒姒、伯服；申侯怒，联缯与犬戎攻周；幽王举烽火而诸侯不至，崩于骊山；平王东迁，秦襄公以兵送之，受封岐西。

**为什么不是电影**：电影可以告诉你「烽火失信 → 诸侯不至 → 西周亡」，但只有让你自己决定「出多少兵、走哪条路、何时动」，你才会体验到：勤王不是一句口号，而是资源、距离、时机与后果的权衡；历史锚点不可改写，但应对方式仍有意义。这是「在不可逆的约束下做选择」的训练，不是「改写历史」的幻想。

## 核心设计命题

**本项目设计主张**：游戏作为历史的载体，最大的作用是让历史知识产生明显的获得感——读到的知识能当场帮你解开游戏里的难关，并立刻得到回报。历史知识因此不是背景气味，而是**可兑现的资产**：它解锁选项、帮你避坑、在结算里换成战斗力/资源/情报/生存优势，并在战报、对话、纪年与奖励里立刻可见。

操作化为四步回路：**识别**（用历史知识看懂局面）→ **选择**（知识解锁或排除选项）→ **结算**（知识进入公式）→ **反馈**（战报、对话、纪年、奖励）。任何一环断了，知识就退回成背景文本。

| 设计选择 | 玩家意义 | 学者论点（来源 + PDF 页） | 你的贡献 |
|---|---|---|---|
| 兵种克制/地形/粮耗 | 知识 = 战斗力 | Harnes 2025：实质知识是历史共情的基础（p.14） | 把知识做成结算项，而不只是理解前提 |
| 勤王时机/路线/兵力 | 知识 = 决策优势 | Harnes 2025：语境化与证据工作是核心瓶颈（p.9） | 把语境做成可失败的选项门槛 |
| 周幽王对话 | 知识 = 情报/社交优势 | Park 2023：记忆流与检索（p.2、p.9）；记忆会漏取与编造（p.15） | 把 agent 的记忆缺陷转成玩家的情报任务 |
| 战报与复盘 | 知识 = 可解释的胜利 | Harnes 2025：共情是认知—情感复合体（p.7），情感需与知识/证据绑定（p.14） | 用逐项战报把「爽」归因到具体知识 |
| 纪年/史料异说 | 知识 = 对史学争论的理解 | Zhang 2023：790–780/772/770 重建（p.18）；771 在平王二年（p.19）；作者自称可检验假设（p.80） | 把纪年争议做成可选情报层，而非脚注 |

**证据边界**：三篇文献只支持三件有限的事——（a）实质知识、语境化与证据工作是历史理解的条件（Harnes 2025, pp.7、9、10、11、14）；（b）LLM agent 的记忆/检索可用但会失败、会编造（Park 2023, pp.2、9、15、17–18）；（c）771 BCE 不是无争议的唯一年份（Zhang 2023, pp.1、18、19、56、80）。它们**不**证明「游戏天然优于电影或教科书」，也**不**证明本实现能提升学习。所谓「其他媒介无法比拟」是作者的设计假设，需用前测/后测、游戏选择日志与复盘来检验。

## 研究问题

1. 怎样把《史记》等原文拆成**可查询、可引证**的结构化数据，而不是把历史当背景文本？
2. 怎样让兵种数值与克制关系**从史学论点长出来**，同时仍然可玩、可平衡？
3. 怎样用程序重绘一张**有经纬锚点、有引文**的战国地图，而不是贴一张底图？
4. 怎样让 LLM 扮演历史人物时**可以即兴，但不能越出史限**？
5. 在「骊山之难」固定的前提下，怎样让玩家的选择仍然**有意义、可结算、可解释**？
6. 怎样让同一套数据支撑数据库、图鉴、雷达、游戏与 Godot 移植，避免数值分叉？
7. 怎样检验「历史知识带来即时优势」不是设计者的自我感觉，而是玩家可感知、可复述、可迁移的经验？

## 方法

1. **原文 → 数据库**：从《史记》全文与《左传》《国语》《战国策》等佐证中抽取 `general / battle / rating`；从《荀子·议兵》《司马法》《吴子》等抽取 `unit / counter`。每条尽量带 `original_text` 与 `citation`。
2. **考据 → 规则**：把「齐技击 < 魏武卒 < 秦锐士」这类比较句翻译成克制系数；把「数年而衰、其税必寡」翻译成高维持费；把服制报告翻译成 190 张立绘的提示词。
3. **地理 → 地图**：87 个省以史载城邑真实经纬为锚点，46×28 网格加权 Voronoi 划格，六边形 R=10 采样，共享 Catmull-Rom 曲线生成有机边界；海岸、大河、山脉、湖泽、北徼全部自绘，不用外部底图。
4. **规则 → 游戏**：HOI4 式回合循环（收入 → 训练 → 调兵 → 进攻/围城 → 事件 → 胜负），战斗按兵种构成、克制、地形、城防、将领、技卡结算。
5. **人物 → agent**：周幽王只接收【纪年】【当前感知】【记忆库】【禁句】，只输出一个动作 JSON（say/goto/stay/silence）；世界判定先行，死亡后封殿，失败时脚本降级。
6. **数据 → 移植**：`_tools\export_godot_data.mjs` 从 Web 版导出 `provinces.json / generals.json / units.json`，Godot 切片直接读取。
7. **验证**：数据库行数核验、地图 `MAP.check()` 孤岛检测、12 回合 AI 压测、浏览器主流程回归、Godot 无头导入与运行截图。

## 证据分级（evidenced / inferred / invented）

课程要求对「地点、物件、人物、行为规则」逐项标记。本项目的分级如下：

| 部分 | 标记 | 依据 / 说明 |
|---|---|---|
| 历史事件（废立、烽火、骊山之难、平王东迁） | **evidenced** | 《史记·周本纪/秦本纪》《国语·周语/郑语》原文 |
| 人物身份、关系、结局 | **evidenced** | 数据库 `general`、周亡 CSV，附原文 |
| 城邑位置与省份锚点 | **evidenced / inferred** | 史载城邑真实经纬；个别位置为推定 |
| 省界几何、六边形边界 | **invented** | 为可玩与可维护而抽象；方位按引文 |
| 海岸、大河、山脉、湖泽 | **evidenced / inferred** | 真实走向的自绘折线；细部为示意 |
| 兵种编制与装备 | **evidenced** | 《司马法》《荀子·议兵》等原文 |
| 兵种六维数值 | **inferred** | 由编制、战例、文献评价折算，非原文直接给出 |
| 13 条克制关系 | **evidenced** | 文献比较句 + 战例；系数为 **inferred** |
| 六维评分与总评 | **inferred** | 由战绩统计 + 原文评价加权；`rationale` 可复核 |
| 人物立绘与服制 | **inferred / invented** | 四时代服制有考据；具体姿态、配色为艺术演绎 |
| 战斗公式、资源、回合 | **invented** | 游戏机制；不主张史学结论 |
| 玩家可行动作 | **invented** | 教学情境的交互设计 |
| 幽王 agent 的记忆/感知 | **evidenced** | 取自本纪所载既行之事；说话风格为 **invented** |
| 骊山之难固定触发 | **invented** | 教学锚点设计，已明示 |

原则：**明文要硬，推定要标，演绎要认，虚构要说明。**

## 工作假设

- 文献中的「比较句」可以转成可玩的克制关系，但必然是有损压缩；只要标出「推定」，就仍可复核。
- 玩家在固定历史锚点下仍有有意义的选择：兵力、时机、路线、资源分配。
- LLM 可以被「记忆白名单 + 感知范围 + 单动作 JSON + 世界判定」约束到可接受范围；但仅靠 prompt 不够，需要后置校验。
- 历史知识可以被设计成「可兑现的优势」（解锁/避坑/结算/反馈），从而产生获得感；但这是设计假设，尚未测量。
- 一套数据可以跨 Web/Godot 复用；导出脚本比手工抄数值更可靠。

## 风险与开放问题

1. **LLM 史限越权**：模型可能说出「秦统一天下」等后事；目前只有输入侧约束。
2. **长局记忆滑窗**：60+ 回合后废立、烽火等关键记忆可能被丢弃。
3. **87 省平衡**：每省 1–3 金/粮、约 1.5 单位驻军的节奏未做 35+ 回合实战校准。
4. **地图精度**：Voronoi 不精确贴太行陉口、淮水两岸；海权缺失。
5. **战斗透明度**：克制/地形/城防系数缺逐项拆解面板。
6. **成本估算**：模型牌价随月变动，中间件按次收费未计入。
7. **Godot 规则对齐**：目前只有浏览与回合骨架，经济/招募/维护/战斗尚未迁移。
8. **文档版本漂移**：`游戏说明.md` 同时出现 v3.1/v3.6/v3.7 与 36/87 省两种口径。
9. **课堂网络**：校园网/防火墙对 `127.0.0.1:8642` 的放行需实测。
10. **获得感未测量**：目前只能证明机制按设计运行，不能证明玩家学得更好；「游戏优于其他媒介」是待检验的设计假设，不是文献结论。
